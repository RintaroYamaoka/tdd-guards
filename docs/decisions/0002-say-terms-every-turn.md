# ADR 0002: 言葉のルールは skill でなく、毎ターンの hook で入れる

- 日付: 2026-11-24
- 状態: 採択

## 文脈
返事・PR・commit message で、コードにある物を言い換えた呼び名で書く癖があった。2026-11-10〜11-24 の transcript(227 session・返事 約 329 万字)で、API・エンドポイント・関数を「口」と書いた所が約 1,000、ステップ・ステージを「段」が約 1,270、ツール・スクリプトを「道具」が 413、コンテナ・コンポーネントを「箱」が 238。言い換えた呼び名は grep できず、読む側(人と次の session の AI)がコードの名前に戻す所で取り違える。

memory に禁止語の一覧(「段」「流す」ほか)を置いていた repo でも、件数は上のとおりで、効いていなかった。

## 決定
- `UserPromptSubmit` の hook(`say-terms.sh`)で、固定の文(`hooks/terms.md`・6 行以内)を毎ターン context に入れる。
- skill には写さない(同じルールを 2 か所に置かない)。skill には所在の 1 行だけ。
- 返事を検査して止める hook(Stop)は足さない。検査できるのは決まった語だけで、「コードの名前を使ったか」は判定できず、「窓口」「入口」の偽陽性が出る。

## なぜ skill でないか
- skill の本文は呼ばれた時しか読まれない。常に context にあるのは説明の 1 行だけ。
- `tdd` が読まれるのは実装の前と commit・push の前。言葉のルールは作業の種類に依らず、コードを書かない session の返事にも掛かる。
- 長い session では冒頭で読んだ文が薄れる。毎ターンの文は常に直近にあり、compaction の後も残る。

## ADR 0001 との関係
0001 は「UserPromptSubmit の割り込み」を継がなかった。あれは並走運用の状態(lane・WO)を読んで割り込む、判断を持つ hook だった。今回の hook は入力を読まず、状態を持たず、固定の文を出すだけ。0001 の線(判断する hook・marker・設定ファイルを持たない)は変えていない。変わるのは README の「音を出すのは止める時だけ」で、これは PreToolUse の 3 本の性質として書き直した。

## 帰結
- 毎ターン 約 100 token 増える。
- 文を長くすると埋もれるので、`terms.md` は 6 行以内(test が見る)。
- 効いたかは数えて確かめる:入れて 1 週間後に同じ集計を回す。残っていたら、そのとき Stop の検査を考える。
